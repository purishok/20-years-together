# 20 років разом ♡

Сайт-привітання українською до двадцятої річниці батьків. Кремово-бордовий дизайн, усі п’ять ваших фотографій, галерея з фільтрами та повноекранним переглядом, особистий лист, 20 побажань і святкова анімація. Адаптований для телефона та комп’ютера; шрифти зберігаються локально, зовнішні сервіси для роботи сайту не потрібні.

## Локальний запуск — два окремі процеси

Потрібні Node.js 22.12+ (або 24), npm, uv і make. uv автоматично знайде або встановить Python 3.13.

Якщо Docker-версія вже працює, спочатку виконайте `make down`, щоб звільнити порт 8000 для локального backend.

Один раз встановіть залежності з кореня проєкту:

```sh
make install
```

У першому терміналі запустіть FastAPI:

```sh
make backend
```

У другому терміналі запустіть React:

```sh
make frontend
```

Сайт: **http://localhost:5173**. Backend: **http://localhost:8000**. Документація API: **http://localhost:8000/docs**. Обидва сервери підтримують автоматичне перезавантаження коду. Для завершення натисніть `Ctrl+C` у відповідному терміналі. Після зміни `backend/app/content.json` перезапустіть backend і оновіть сторінку.

Frontend звертається до `/api` через проксі Vite. Backend працює окремо й не роздає React. За потреби адресу проксі можна змінити: `API_PROXY_TARGET=http://127.0.0.1:9000 make frontend`.

## Docker — два окремі контейнери

Запустіть Docker Desktop, потім:

```sh
make up
```

Відкрийте **http://localhost:8080**. React збирається в статичні файли й працює через Nginx; FastAPI працює в окремому контейнері на порту 8000. Nginx пересилає `/api` до backend через внутрішню мережу Docker. Compose очікує готовності API перед стартом frontend.

Окремий запуск кожної частини:

```sh
make docker-backend
make docker-frontend
```

`make docker-frontend` запускає тільки frontend, без автоматичного запуску backend. Для завантаження привітання потрібен запущений backend.

```sh
make logs  # логи обох сервісів
make down  # зупинка
```

## Персоналізація

- `backend/app/content.json` — звернення, текст листа, підпис, 20 побажань, порядок фото та підписи до них. Імена та точна дата не вигадані; їх можна додати до привітання.
- `frontend/public/photos/` — справжні копії всіх п’яти наданих фото. Початкові посилання на кеш Telegram залишені без змін, але більше не потрібні для роботи сайту.
- `frontend/src/App.tsx` — тексти основних секцій.
- `frontend/src/styles.css` — кольори, типографіка й адаптивне оформлення.

Перегляд фото підтримує кнопки, стрілки клавіатури, свайпи та `Escape`. Діалоги утримують фокус і повертають його після закриття. Сайт враховує системне налаштування зменшення анімацій. Кнопка «Поділитися теплом» відкриває системне меню або копіює посилання, якщо браузер це підтримує. Для перегляду з іншого пристрою потрібна доступна йому адреса: `localhost` працює лише на поточному комп’ютері.

## Перевірки

```sh
make test   # API, наявність фото, TypeScript
make build  # production-збірка React
cd frontend
npm run test:e2e
```

Браузерні перевірки використовують установлений Google Chrome: перевіряють desktop/mobile, фото, фільтри, лист, перемикання побажань, навігацію та повторне завантаження після помилки API. Playwright автоматично запускає сервери, якщо вони ще не працюють.

Для перевірки вже запущеної Docker-версії з папки `frontend`: `E2E_BASE_URL=http://127.0.0.1:8080 npm run test:e2e`.

Команди створення контейнерів потребують інтернету для першого завантаження базових образів і залежностей. Ні фото, ні привітання не відправляються до сторонніх API.

Технічні довідки: [Vite](https://vite.dev/guide/), [FastAPI у Docker](https://fastapi.tiangolo.com/deployment/docker/), [uv у Docker](https://docs.astral.sh/uv/guides/integration/docker/).
